# Deploying SeatLock for free: Vercel + Render + Neon + Upstash

The hosted demo runs on four free services. No credit card is needed for any of them (as of November 2026; check each sign-up page).

```
Browser ──▶ Vercel (React site, seatlock-xxx.vercel.app)
               │  /api/* forwarded, with a secret header added
               ▼
            Render (one free web service: API + worker + mock gateway, Singapore)
               │                       │
               ▼                       ▼
            Neon (PostgreSQL)      Upstash (Redis, rate limiting only)
```

**Order matters:** Neon and Upstash first (Render needs their URLs), then Render (Vercel needs its URL), then Vercel.

Pick **Singapore** (or the closest Asia region offered) everywhere: the closest to India, and keeping all three in one region keeps the database round trips short.

## What you need

- A GitHub account (all four services sign in with it).
- About 45 minutes.
- Three passwords you make up yourself, at least 32 characters for the first one. Generate them in PowerShell:

```bash
node -e "for (const n of ['ORIGIN_SECRET','SEED_ADMIN_PASSWORD','SEED_DEMO_PASSWORD']) console.log(n, require('crypto').randomBytes(24).toString('base64url'))"
```

Keep the output in a password manager or a private note. **Never commit it or paste it into a chat.**

---

## 1. Neon (PostgreSQL)

1. Go to https://neon.com and **Sign up with GitHub**.
2. Create a project: name `seatlock`, Postgres **16** (or the newest offered), region **AWS Asia Pacific (Singapore)**.
3. On the project dashboard, click **Connect**. Turn **Connection pooling OFF** (we want the _direct_ connection: SeatLock sets per-connection timeouts, which the pooler drops).
4. Copy the connection string. It looks like:
   `postgresql://neondb_owner:...@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
   It must **not** contain `-pooler`. This is your `DATABASE_URL`.

## 2. Upstash (Redis)

1. Go to https://upstash.com and **sign in with GitHub**.
2. **Create Database** → Redis, name `seatlock`, type **Regional**, region **ap-southeast-1 (Singapore)**, eviction off.
3. On the database page, copy the **TLS** connection URL that starts with `rediss://` (two s). This is your `REDIS_URL`.

## 3. Render (the backend)

1. Go to https://render.com and **sign up with GitHub**. Allow it access to the `SeatLock` repository.
2. **New → Blueprint**, pick the `SeatLock` repository. Render reads `render.yaml` and proposes one free web service named **seatlock-api**.
   - If the name `seatlock-api` is taken, Render gives the service a different address; note it for step 4.
3. Fill in the values it asks for:

| Variable              | Value                             |
| --------------------- | --------------------------------- |
| `DATABASE_URL`        | The Neon direct connection string |
| `REDIS_URL`           | The Upstash `rediss://` URL       |
| `ORIGIN_SECRET`       | The first generated value         |
| `SEED_ADMIN_PASSWORD` | The second generated value        |
| `SEED_DEMO_PASSWORD`  | The third generated value         |

`JWT_SECRET` and `WEBHOOK_SECRET` are generated by Render automatically.

4. **Apply**. The first deploy builds (about 3–5 minutes), runs the migrations, seeds the catalogue and starts. In **Logs** you should see, in this order: `Migrations complete!`, `Catalogue ready: 14 movies...`, `mock gateway listening`, `api listening`, `database timeouts applied`, `redis connected`, `worker started`.
5. Copy the service address shown at the top, e.g. `https://seatlock-api.onrender.com`. Check `https://seatlock-api.onrender.com/api/health` in the browser: `{"status":"ok","db":"up","redis":"up"}`.
6. Check that `https://seatlock-api.onrender.com/api/movies` answers **403** ("Requests must come through the website"). That is correct: only Vercel may call it.

> **If the logs say `database timeouts NOT applied`:** the connection string is the pooled one. Use the direct one (step 1.3).

## 4. Vercel (the website)

1. If Render named the service something other than `seatlock-api`, edit `frontend/vercel.json`: replace `https://seatlock-api.onrender.com` with your Render address, commit and push.
2. Go to https://vercel.com and **sign up with GitHub** (Hobby plan).
3. **Add New → Project**, import `SeatLock`.
4. **Root Directory:** `frontend`. Framework: **Vite** (detected). Leave the build settings as detected.
5. **Environment Variables:**

| Name                 | Value                                            |
| -------------------- | ------------------------------------------------ |
| `ORIGIN_SECRET`      | The same value as on Render                      |
| `VITE_DEMO_EMAIL`    | `demo@seatlock.app`                              |
| `VITE_DEMO_PASSWORD` | The same value as `SEED_DEMO_PASSWORD` on Render |

6. **Deploy**. You get an address like `https://seatlock-xxx.vercel.app`. In **Settings → Domains** you can change the free name to something cleaner, e.g. `seatlock-booking.vercel.app`, if it's free.

The demo account's password is shown to anyone who opens the sign-in page; that is intended. It is an ordinary customer account. The admin password is never in the website.

## 5. Check the live site

- [ ] Open the Vercel address. If the backend was asleep you see **"Waking up the server..."** for up to a minute, then the films.
- [ ] **Continue with the demo account** on the sign-in page works.
- [ ] Book: showtime → seats → Hold → Pay → ticket. Cancel it in My bookings → "Refunded" within about 10 seconds.
- [ ] Open the site on your phone.

## How it behaves on free plans

| What                                            | Effect                                                 | Why it's safe                                                                                                                           |
| ----------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Render sleeps after 15 minutes without visitors | The first visit takes up to a minute; the site says so | Pending work (outbox events, expiries, payments) is in Postgres and resumes on wake. Expired holds already show as free on the seat map |
| The worker stops while asleep                   | Expiry, refunds and notifications wait                 | Nothing is lost; the seat map's read-time rule doesn't depend on the worker                                                             |
| Neon pauses after 5 idle minutes                | The first query takes about a second longer            | Nothing keeps it awake artificially, so the free compute (100 CU-hours/month) lasts                                                     |
| Showtimes                                       | Topped up on every start and every 6 hours             | Old unbooked shows are deleted daily to stay under Neon's 1 GB                                                                          |

**Don't add an uptime pinger.** Keeping Render awake would keep the worker polling Neon around the clock and use up Neon's free compute (100 CU-hours, about 400 hours at the smallest size) in roughly two and a half weeks.

## Before an interview

Open the site a minute before, so the backend is awake when you share your screen.

## Redeploying

Push to `main`: Render and Vercel both rebuild automatically. A new database migration runs on the next Render start.

## Security notes

- The backend accepts API calls only through Vercel (`ORIGIN_SECRET`, checked in constant time). Webhooks and the health check are exempt: webhooks carry their own HMAC signature.
- The login rate limit uses the visitor's real IP from Vercel's `x-real-ip` header, trusted only because the origin secret proves the request came through Vercel.
- API responses are `Cache-Control: no-store`, so Vercel's edge never caches anyone's bookings.
- The mock gateway listens on `127.0.0.1` only, and its failure-mode switch is off.
- There is no default admin password in production; the admin exists only if `SEED_ADMIN_PASSWORD` is set.
